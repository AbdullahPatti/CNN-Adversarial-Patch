PART A. STATUS (Phase 4 onwards)
--------------------------------

1. Phase 4 - Patch transfer (RQ2), running
   - Patches from all 13 source models are pasted on all 13 target models
     (full 13 x 13 matrix: full->compressed, compressed->full, and
     compressed<->compressed), plus a 5 x 5 matrix for the physical-EOT patches.
   - The diagonal reproduces the Phase 3 numbers exactly (baseline U5 81.1 / 6.7,
     U8 61.2 / 35.3), so the transfer evaluation measures the same thing as Phase 3.
   - Each LaVAN transfer rate is shown next to a random-noise patch at the same
     locations, so occlusion is not counted as transfer.
   - Code: src/transfer.py, configs/phase4/transfer.yaml; tables in src/report.py.

2. Bug found and fixed
   - Phase 3 saved LaVAN patches at reduced precision (FP16). LaVAN stops as soon
     as it fools the model, so patches sit right on the decision boundary.
   - The FP16 rounding pushes some back across INT8 quantization bins: the INT8
     model's own patches fool it only 87.6% of the time on replay (FP32 models: 99.8%).
   - Fixed: src/attack.py now saves full-precision (FP32) patches for all future runs.
     Seed-42 transfer numbers are "patch as stored"; the diagonal shows the effect size.

3. Phase 5 - PatchCleanser certification (RQ3), code done and tested
   - Mask set: 6 positions per axis; side 5 -> 36 masks of 9 px, side 8 -> 25 masks
     of 12 px. Coverage of every patch position is checked in tests/test_smoke.py.
   - The ordinary (vanilla) baseline certifies only 10.7% (side 5) / 2.1% (side 8)
     at 95% clean accuracy - too close to zero to compare compression methods.
   - Decision: train a second "defended" set of 13 models. The baseline is retrained
     with PatchCleanser-style mask augmentation, then compressed, with masking kept
     on in every fine-tune / QAT / distillation run (defend, then compress).
   - Vanilla certification is still reported as the reference point.
   - Code: src/defense/patchcleanser.py, src/certify.py, configs/phase5/.

4. Journal rigor
   - Seeds 43 and 44 now run the whole pipeline (models, attacks, transfer,
     certification). Attack seed unchanged, so seeds are paired comparisons.
   - New runs keep the final training epoch instead of the best test-set epoch, so
     the test set plays no part in training. On seed 42 the two differ by <= 0.13 pp
     in every run (checked from the training logs).
   - Configs generated by src/seed_configs.py (configs/seed43, seed44, seed4X_def).

5. GPU queue (~66 GPU-hours, ~3 days)
   - Starts automatically when Phase 4 finishes; restartable (finished runs are skipped).
   - Order: defended seed-42 models -> certification of seed 42 (vanilla + defended)

PART B. WHAT THE 66 HOURS ARE FOR
---------------------------------

Measured on the RTX A4000 for seed 42:
  - one full set of 13 models (baseline + 12 compressed): ~9 h of training
  - Phase 3 attacks on one set: ~7 h
  - Phase 4 transfer matrix: ~1.5 h
  - certification: ~3-6 min per model

Job                    What it is                                   Count       Hours
---------------------  -------------------------------------------  ----------  --------
Train model sets       defended seed 42; normal + defended          5 x 9 h     ~45
                       for seeds 43 and 44
Phase 3 attacks        normal sets, seeds 43 and 44                 2 x 7 h     ~14
Phase 4 transfer       seeds 43 and 44                              2 x 1.5 h   ~3
Phase 5 certification  77 models                                    3-5 min ea  ~4-6
---------------------  -------------------------------------------  ----------  --------
TOTAL                                                                           ~66-68

Within training, the 200-epoch runs take most of the time (baseline, dense-small,
distillation students: 7 per set, ~75-90 min each). Pruning fine-tunes, INT4 QAT and
the FP16 / INT8 conversions are short.

Why each part is there:
  - Seeds 43/44 (~35 h): right now every number comes from one training run. Many
    Phase 3 differences are only 2-3 points, which one seed cannot separate from
    noise. A journal reviewer will ask for mean +/- std over seeds.
  - Defended set (~27 h over 3 seeds): without mask training, certified accuracy is
    near zero (10.7% / 2.1%), so the certification result (RQ3, the lead
    contribution) needs these models.

Ways to cut it if the GPU is needed elsewhere:
  1. Defended set at 4x only (baseline + the four 4x models, ~4.5 h per seed
     instead of 9 h): saves ~13 h. Certification is then compared at one size
     ratio rather than the 2x / 4x / 8x trend.
  2. Defended set for seed 42 only: saves ~18 h, but certification numbers would be
     single-seed while attack numbers have three seeds.
  3. Drop seed 44: saves ~22 h, but two seeds give a weak std. Not recommended
     for a journal.

Recommendation: keep the full plan. If the GPU is needed back sooner, option 1 is
the cheapest cut with the least loss to the study. The queue skips anything already
finished, so it can be stopped, reordered or trimmed at any point without losing work.
